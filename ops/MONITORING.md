# External availability monitoring

HetrixTools now monitors `https://chog-api.72-56-98-23.sslip.io/api/health` every minute from New York, Amsterdam and Frankfurt. Two of three locations must fail; timeout is ten seconds, with the configured per-location retries. Contact list `Chog Arena - Telegram` uses HetrixTools' own bot. The owner supplied its private-chat identifier directly for this purpose; it and the separate application bot token are not recorded here. The report remains private.

The route returns a bounded public summary and `Cache-Control: no-store`. It runs before demo session creation or game ticking. Demo reports `mode: demo` and explicitly says a keeper is not required; demo availability is not proof that the future live keeper is healthy. In live mode the route returns HTTP 503 for a missing, invalid, stale, errored, revoked, fee-capped, stuck or excessively backlogged keeper heartbeat. It reads only the sanitized heartbeat, not the transaction journal or credentials. A recent ready heartbeat is an operational signal, not proof that every game or external dependency is correct.

A controlled absent-keyword test produced DOWN at 02:51 and recovery at 02:53 Moscow time on 22 October 2026. The normal keyword `"status":"ok"` was restored and the report showed Online. The website was not stopped. Confirm human receipt separately; a status transition alone does not prove notification delivery. The application monitor was also run once in its real isolated systemd unit with the intentional bootstrap condition MONITOR_FAILED. Telegram acknowledged that message and delivery state persisted; the expected exit 2 was reset. Its timer remains disabled until a real arena and release checks are ready.

The service rejected direct monitoring of the Netlify hostname. This setup detects API/VPS/DNS/TLS unavailability, including loss of the host that sends the separate application alerts. It does not independently monitor Netlify frontend availability or a complete wallet/match journey. The VPS monitor cannot send its own alerts during total host/network loss, hence this independent check. Before live launch also complete full match coverage and real reveal-capacity tests; SEC-03/04 remain open.

Manage it in https://hetrixtools.com/dashboard/uptime-monitors/ . Keep the free account active by logging in at least once every 90 days under the current free-plan terms. Check your contact list and alerts after account/bot changes. Do not publish diagnostic links containing access tokens or paste bot credentials into reports. Respond to a real alert by checking the public route, VPS services and bounded public condition codes, then follow `ops/RECOVERY.md`; notification does not itself revoke a keeper.

## Repeating the offline host measurement

`scripts/benchmark-keeper.mjs 32` uses a historical signed drand fixture and no wallet/provider. Run only in a separate validation folder with the required fixture, public libraries and production dependencies. On the VPS it ran under a transient DynamicUser unit, PrivateNetwork, ProtectSystem=strict, ProtectHome, PrivateTmp, 768 MiB and one CPU. All 32 commitments/nonces validated and 1000 malformed ciphertexts were rejected. Mean decryption was 106 ms and p95 112 ms. These are CPU/crypto measurements, not chain throughput; RPC, signing, gas, confirmations and concurrent traffic are excluded.

`node --test test/keeper-durable.test.mjs` also passed all eleven cases in the same isolation. Its provider and wallet are test doubles. The first invocation could not import ethers because the validation node_modules link was absent; after correcting the test folder the full run passed. No production signing file was available to either test.

`ops/configure-health.sh` installs the reviewed health-only patch from `/root/chog-health-code`, takes a consistent backup, switches releases atomically and restarts only the web service with rollback on activation failure. The installed patch and evidence are recorded in `security/operational-readiness.json`. No funds, keeper start or release decision is included.
